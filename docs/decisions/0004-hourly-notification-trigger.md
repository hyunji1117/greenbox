# 0004. 사람마다 정한 시각에 알림을 보내기 위한 매시간 실행

- 날짜: 2026-11-06
- 상태: 결정

## 배경

유통기한 알림은 하루 한 번, 오전 9시에 모든 사람에게 같은 시각으로 보냈다.
가족 사용자 2명에게 알림 받기 편한 때를 물었더니 답이 갈렸다.

| 질문 | 사용자 A | 사용자 B |
|---|---|---|
| 알림 받기 편한 때 | 저녁 먹기 전 | 오전 |
| 장 보는 때 | 주말 오후 | 주말 오후 |
| 알림이 오지 않았으면 하는 시간 | 없음 | 오후 8시 이후 |

- 가설: 한 가족 안에서도 생활 시간이 달라, 정해진 한 시각은 누군가에게 맞지 않는다 → 맞았다
- 그래서 하루 요약 시각을 사람마다 정하고, 장보기 전에 받는 주간 요약을 더한다

## 문제

시각을 사람마다 정하려면 발송 작업이 매시간 깨어나 "지금 보낼 사람이 있는지" 확인해야 한다.
지금 쓰는 Vercel 무료 플랜의 예약 작업은 하루 1회까지만 된다.

## 검토한 방법

| 방법 | 비용 | 관리 | 정확도 | 판단 |
|---|---|---|---|---|
| GitHub Actions 예약 실행 | 무료 | 저장소 파일 1개, 리뷰 가능 | 몇 분 늦거나 드물게 건너뜀 | 채택 |
| Vultr 서버 cron | 월 $5 안팎 | 서버 보안, 업데이트, 장애 대응 | 정확 | 보류 |
| Vercel 유료 플랜 | 월 $20 | 없음 | 정확 | 보류 |
| 시각 설정 없이 하루 1회 유지 | 무료 | 없음 | 해당 없음 | 사용자 답과 맞지 않아 제외 |

Vultr 서버는 cron 하나만을 위해 두기에는 관리 부담이 크다.
실시간 연결(동시 수정)이나 Streaming SSR 서버를 직접 운영하게 되면 그때 서버를 두고 예약 실행도 옮긴다.

## 결정

- GitHub Actions가 매시간 5분에 발송 API(`/api/cron/notifications`)를 호출한다. `CRON_SECRET`으로 인증한다
- Vercel 하루 1회 예약 작업은 같은 API를 부르는 예비 실행으로 남긴다
- 늦거나 건너뛴 실행에 대비해, 정한 시각부터 2시간 안에는 아직 안 보낸 사람에게 보낸다
- 발송 기록(`notification_sends`)으로 하루 요약은 하루 1번, 주간 요약은 주 1번만 보낸다. 실행이 겹쳐도 중복되지 않는다
- 알림은 "정각"이 아니라 "정한 시각대 안에" 도착한다고 안내한다

## 기본값

- 하루 요약: 오전 8시 (처음 묻는 화면에서 아침 8시 / 점심 12시 / 저녁 준비 전 5시 중 고른다)
- 주간 요약: 토요일 12시 (두 사용자 모두 주말 오후에 장을 봐서, 나가기 전에 도착하게)
- 밤 시간: 요약 알림은 고른 시각에만 가므로 따로 막지 않는다. 참여 요청처럼 바로 가는 알림은 지금처럼 바로 보낸다
  (밤에 미루려면 보낼 알림을 쌓아 둘 곳이 필요해, 요청이 생기면 다시 본다)

## 측정

실행마다 다음 값을 GitHub Actions 실행 요약과 Vercel 로그에 남긴다 (사람 정보 없음).

- 실행 시각과 정각에서 늦은 분 (`delayMinutes`)
- 하루 요약과 주간 요약 각각: 시각이 된 사람 수, 실제로 보낸 사람 수, 보낸 기기 수, 실패 수, 지운 기기 수

호출이 실패하면 작업이 실패로 끝나 메일로 알림이 온다.

출시 뒤 확인할 지표

- 하루 요약 시각을 기본값에서 바꾼 사람 비율
- 시각대별 알림을 눌러 들어온 비율 (알림 클릭 측정은 아직 없어 다음 작업으로 남긴다)
- 예약 실행 지연 분포. 30분을 자주 넘기면 다른 방법을 다시 검토한다
