# 0006. 등록할 때 유통기한을 권장 보관 기간으로 자동으로 채운다

- 날짜: 2026-11-08
- 상태: 결정

## 배경

사용자는 식재료를 넣을 때 유통기한을 거의 적지 않는다. 날짜가 비어 있으면 냉장고 화면의 남은 날 표시도,
정한 시각에 오는 요약 알림도 동작하지 않는다. 같은 식재료라도 보관 위치에 따라 먹을 수 있는 기간이 다르다
(떡은 상온이면 하루, 냉동이면 두 달).

## 결정

- 등록할 때 유통기한을 비워 두면 서버가 "등록일(한국 날짜) + 권장 일수"로 채운다
  - 입력 등록, 사진으로 등록, 장보기 구매 완료 모두 같은 API를 거치므로 한 곳에서 처리한다
  - 직접 넣은 날짜가 있으면 그 날짜가 우선이고, 채운 날짜는 냉장고 화면에서 언제든 고칠 수 있다
- 권장 일수는 "식재료 이름 x 보관 위치(냉장, 냉동, 상온)" 표에서 찾는다 (`app/lib/items/storageGuide.ts`)
  - 이름에 낱말이 들어 있으면 맞춘다 (예: "국내산 닭가슴살" → 닭가슴살). 긴 낱말이 먼저 맞는다
  - 표에 없으면 보관 위치 기본값: 냉장 5일, 냉동 30일, 상온 14일
- 등록 직후 "유통기한은 권장 기간으로 채웠어요. 다르면 바꿔 주세요"를 보여 참고값임을 알린다
- 이미 등록된 품목의 빈 유통기한은 채우지 않는다 (사용자가 일부러 비워 둔 것일 수 있음)

## 근거와 한계

- 냉장, 냉동 기간: 미국 농무부 FoodKeeper의 보관 기간을 바탕으로, 범위가 있으면 짧은 쪽을 골랐다
- 냉동 기간: 식약처 냉동 보관 안내(익히지 않은 생선과 해산물 3개월, 냉동은 품질이 유지되는 한계)
- 식품 안전을 보장하는 값이 아니라 "이쯤 먹으면 좋다"는 참고값이다. 실제 제품의 유통기한과 보관 상태가 우선이다
- 표의 값은 공개 자료를 참고해 정리한 것으로, 품목별 원문 대조는 이후에 보강한다

## 검토한 다른 방법

| 방법 | 판단 |
|---|---|
| 표에 없는 품목을 AI로 추정 | 더 정확하지만 등록마다 사용료와 지연이 생겨, 표와 기본값으로 먼저 시작 |
| 자동 날짜에 "권장" 표시를 따로 저장 | 화면에서 직접 넣은 날짜와 구분할 수 있지만 DB 변경이 필요해, 등록 직후 안내로 대신 |

## 측정

- 등록 뒤 자동으로 채운 날짜를 사용자가 고친 비율 (높으면 표의 값을 다시 본다)
- 유통기한이 있는 품목 비율과 요약 알림을 받은 사람 수 변화
