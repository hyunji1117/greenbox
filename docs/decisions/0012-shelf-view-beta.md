# 0012. 냉장고 모양 선반 보기 베타와 실험 기반

- 날짜: 2026-11-12
- 상태: 설계 (구현 전). 시안 2026-11-12 사용자 피드백 반영: 양문형 닫힘 → 문 열림, 이미지 선반, 빈 선반만 줄이기

## 배경

두 번째 가족 테스트(2026-11-11, 36분 녹취와 메모)에서 "냉장고 모양으로 보면 어디에 무엇이 있는지 바로 알 것 같다"는 의견과 그림이 나왔다.
첫 가족 관찰(2026-11-10)에서는 저장은 성공했는데 냉동실에 들어간 품목을 찾지 못해 다시 넣는 일이 있었다. 지금 화면은 칸(냉장/냉동/상온) 탭과 카드 목록이라, 품목이 실제로 어디쯤 있는지는 보여 주지 않는다.

## 가설

- H-S1: 선반 보기(B)에서 사용자는 목록(A)보다 특정 식재료를 도움 없이, 같거나 짧은 시간에 찾는다
- H-S2: 선반 보기에서 사용자는 "어느 선반에 무엇이 있는지" 화면만 보고 말할 수 있다
- 안전 가설: 선반을 줄이거나 보기를 바꿔도 품목이 사라지거나 다른 냉장고에 보이지 않는다

사용자가 적어 통계 A/B로 결론 내지 않는다. 금요일에는 한 가족 두 사람이 두 화면을 모두 써 보는 비교(순서를 서로 반대로)를 하고, 결과는 사실과 해석을 나눠 적는다.

## 결정

### 1. 실험 기반을 먼저 만든다 (공용 모듈)
- 알림 A/B에 쓰던 배정 해시를 `app/lib/experiments`로 옮겨 공용 배정 함수로 쓴다. 알림 A/B의 배정 결과는 바뀌지 않아야 한다(같은 입력, 같은 결과를 테스트로 고정)
- 실험 정의: 키, 단위(사람/냉장고), 변형 목록, 대상(허용 목록과 비율). 선반 보기는 단위가 냉장고이고, 처음에는 허용 목록(테스트 가족 냉장고)만 켠다
- 대상 판정은 서버에서 한다. 화면은 서버가 준 변형만 따른다 (기기마다 다르게 보이지 않게)
- 노출 기록: 실험 화면을 처음 본 때 `experiment_exposed`(실험, 변형)를 남긴다

### 2. 데이터는 추가만 한다 (마이그레이션 0015)
- `items.shelf`: 선반 번호(1부터, 비어 있으면 "선반 미정"). 비어도 되는 칸이라 예전 코드는 그대로 동작한다
- `fridge_shelves`: 냉장고와 칸마다 선반 수(기본 5, 1~7)
- 선반은 비어 있을 때만 줄일 수 있다. 식재료가 있는 선반을 줄이는 요청은 서버에서도 거부해 품목이 사라질 길을 막는다

### 3. 화면 (B만)
- 양문형 냉장고가 닫힌 채로 보이고, 누르면 문이 양쪽으로 열리며(움직임 줄이기 설정이면 바로 열림) 왼쪽 냉동실, 오른쪽 냉장실 선반이 보인다
- 선반마다 배경 없는 식재료 그림(Fluent Emoji 3D, MIT)을 위아래 두 줄, 줄마다 5개씩 최대 10개 왼쪽 아래부터 놓고 이름을 바로 아래에 둔다. 나머지는 선반을 눌러 목록에서 본다. 그림이 없으면 첫 글자 원
- 한 선반에는 최대 20개까지 넣는다 (서버에서도 거부)
- 선반을 누르면 지금 냉장고 목록 화면이 그 선반 품목만 보이는 상태로 열린다. 거기서 등록, 수량, 알림 설정을 지금처럼 하고, 여기서 넣은 품목은 그 선반에 놓인다
- 베타 목록은 그림 없이 한 줄로 촘촘하게: 이름과 총수량, 남은 날, 알림 종, 다 먹음(2개 이상 남았으면 몇 개 먹었는지 고름). 품목을 누르면 수량, 유통기한, 선반 옮기기, 버림, 기록(누가 언제 넣었는지)을 시트로 보여 준다. 유통기한은 지금처럼 권장 기간으로 자동으로 채운다
- 문이 열리면 "문 닫기"로 다시 닫을 수 있다 (문 앞은 다음 단계의 가족 게시판 자리). 선반 목록에 갔다 와도 문은 열린 채로 돌아온다
- 선반을 정하지 않은 품목(예전 품목 포함)은 "선반 미정"에 모인다
- 선반 추가와 줄이기는 칸 아래 버튼. 줄이기는 비어 있는 선반만 되고, 빈 선반이 없으면 버튼을 끄고 "옮기거나 다 먹음으로 비운 뒤"라고 알린다
- 베타가 켜진 냉장고는 선반으로만 보인다. 화면 안 목록/선반 전환은 두 화면이 섞여 헷갈려 빼고, 비교는 설정의 베타 스위치(주인)로 끄고 켜서 한다
- 냉장고 아래: 나의 메모(이 기기에만 저장) | 지금 날씨(서울, Open-Meteo, 위치 권한 없음), "오늘 뭐 먹지" 3개, 빨리 먹어야 할 식재료(유통기한 3일 안, 1개 이하로 남은 것)
- "오늘 뭐 먹지"는 앱에 넣어 둔 집밥 레시피에서 곧 먹어야 할 재료, 있는 재료, 계절과 날씨 순으로 고른다. 무엇을 먹을지 정해야 장을 보므로, 빠진 재료는 장보기에 바로 담는다. 외부 영상은 앱을 떠나게 해 쓰지 않는다
- 가족은 같은 냉장고의 같은 선반 배치를 본다 (선반은 냉장고에 속함)

### 4. 계측
- `experiment_exposed`(experiment, variant), `shelf_view_toggled`(view), `item_shelf_set`(from, to), `shelf_count_changed`(category, count, action: add/remove)
- 냉장고 아래: `meal_suggestion_opened`(recipe, rank, uses_soon), `meal_suggestion_missing_added`(recipe, count), `urgent_item_opened`(reason)
- 기존 찾기 이동과 품목 이벤트에 `view`(list/shelf)를 붙인다
- 맞춤 측정기준(experiment, variant, view)을 등록하고 BigQuery로 순서를 본다

### 5. 안전 장치
- 기본은 꺼짐. 허용 목록에 없는 냉장고는 지금과 똑같다
- 끄면 바로 목록으로 돌아오고, 선반 번호는 남아 다시 켜면 그대로 보인다
- 선반 변경 API는 그 냉장고 구성원만 할 수 있다 (기존 품목 권한 검사 재사용)
- 회귀 테스트: 식재료가 있는 선반 줄이기 거부, 다른 냉장고 품목 선반 변경 거부, 실험 밖 냉장고는 목록 그대로

## 하지 않는 것

드래그 앤 드롭, 선반 이름 붙이기, 사람마다 다른 배치, 자동 선반 추천, 애니메이션 다듬기. 테스트에서 필요가 확인되면 다음 단계로 둔다.

## 판단 기준 (테스트 전에 고정)

- 유지: 두 사람 모두 선반 보기에서 도움 없이 찾고, 목록보다 느리지 않으며, 선반 배치를 말로 설명할 수 있다
- 수정: 찾기는 되지만 선반 정하기(넣은 뒤 배치)에서 막힌다 → 배치 흐름만 고친다
- 버리기: 선반 정하기가 부담이라 쓰지 않겠다고 하거나, 목록보다 분명히 느리다 → 목록 유지, 칸 표시 강화로 방향 전환
- 품목 유실이나 다른 냉장고 노출이 한 번이라도 있으면 즉시 끄고 원인부터 고친다
