# 0011. 웹앱을 감싼 모바일 앱 셸 (React Native + Expo)

- 날짜: 2026-11-09
- 상태: 결정 (1단계: 웹뷰 셸, 2단계: 심사 준비, 3단계: 스토어 제출)

## 배경

구글 플레이와 앱스토어에 내려면 앱이 있어야 하고, 알림에 사이트 주소 대신 앱 이름이 보여야 한다.
화면을 모두 네이티브로 다시 만들 필요는 없어서, 지금 웹앱을 웹뷰로 열고 웹뷰에서 어려운 일만 앱이 맡는다.

## 결정

- 같은 저장소의 `mobile/`에 Expo(React Native) 앱을 둔다. 웹 검사 도구(tsc, eslint, vitest)와 Vercel 배포에서는 제외한다
- 웹뷰(`react-native-webview`)로 운영 웹앱을 연다. 안전 영역, 안드로이드 뒤로 가기, 외부 링크는 브라우저로, 로딩과 오류 화면, 메모리 부족 시 다시 불러오기를 앱이 처리한다
- 앱과 웹 메시지 통로: 앱이 화면 전에 `window.GreenboxApp`(플랫폼, 앱 버전, post)을 심고, 웹은 `post({ type })`로 공유, 외부 열기, 준비 신호를 보낸다
- 구글 로그인: 구글은 앱 속 웹뷰 로그인을 막으므로 시스템 브라우저(iOS ASWebAuthenticationSession, 안드로이드 Custom Tabs)로 로그인하고 웹뷰로 넘겨받는다
  - 앱이 무작위 비밀값을 만들고 지문만 `/mobile/login`에 넘긴다
  - 로그인 뒤 `/api/mobile/handoff`가 로그인 정보와 지문을 담은 2분짜리 코드를 `greenbox://auth`(개발 중 Expo Go 주소)로 돌려준다
  - 앱이 웹뷰에서 `/api/mobile/session?code=&verifier=`를 열면 지문이 맞을 때만 로그인 쿠키를 심는다 (PKCE와 같은 방식, 코드를 가로채도 쓸 수 없다)
  - 돌아갈 앱 주소는 `greenbox://auth`와 Expo Go 주소만 허용한다
